## ၁။ မိတ်ဆက် - Database နှင့် DBMS အခြေခံ

Beginner တစ်ဦးအနေဖြင့် ပထမဆုံး သိရှိရမည့် အခြေခံမှာ:
* **Data**: "Aung Aung", "35000", "091234567" စသည့် အချက်အလက်များ။
* **Database (DB)**: အဆိုပါ အချက်အလက်များကို သိမ်းဆည်းရာ ဒစ်ဂျစ်တယ် ဗီရိုကြီး။
* **DBMS (Database Management System)**: အဆိုပါ ဗီရိုကြီးကို စီမံခန့်ခွဲပေးသော စနစ် (ဥပမာ- MySQL, PostgreSQL, Oracle)။

### ရိုးရိုး Excel Sheet ထဲ မသိမ်းဘဲ ဘာကြောင့် DBMS သုံးရသလဲ?
1. **Excel သည် လူ ၁ ယောက်သာ စာရင်းသွင်းနိုင်သည်**: လူ ၁ သောင်းက တစ်ပြိုင်နက် ပစ္စည်းဝယ်ယူသည့်အခါ Excel ဖိုင် ပျက်စီးသွားမည်။ MySQL သည် လူ သိန်းနှင့်ချီ၏ Request များကို မီလီစက္ကန့်ပိုင်းဖြင့် တစ်ပြိုင်နက် ဖြေရှင်းပေးနိုင်သည်။
2. **Data Integrity (အမှားမခံနိုင်ခြင်း)**: Excel ထဲတွင် အသက်နေရာ၌ စာသားရိုက်ထည့်၍ ရသော်လည်း MySQL ထဲတွင် `INT` ဟု သတ်မှတ်ထားပါက စာသားရိုက်ထည့်၍ လုံးဝ မရပါ။

## ၂။ Relational Database ဆိုတာဘာလဲ?

**Relational Database (RDBMS)** ဆိုသည်မှာ အချက်အလက်များကို တစ်နေရာတည်းတွင် အကုန်ရောပြွန်းမသိမ်းဘဲ သက်ဆိုင်ရာ **ဇယား (Tables)** အသီးသီး ခွဲထုတ်သိမ်းဆည်းပြီး ၎င်းတို့အချင်းချင်း **ဆက်စပ်မှု (Relations)** ပြုလုပ်ထားသော စနစ် ဖြစ်သည်။

### ဥပမာ:
* စာအုပ်ဆိုင်တစ်ဆိုင်တွင် စာအုပ်ရောင်းသည့်အခါ "စာအုပ်အမည်၊ ဈေးနှုန်း၊ ဝယ်သူနာမည်၊ ဝယ်သူဖုန်း၊ ဝယ်သူလိပ်စာ" အားလုံးကို အတန်းတစ်ခုတည်းတွင် အမြဲလိုက်ရေးနေမည်ဆိုပါက မောင်မောင်သည် စာအုပ် ၁၀ အုပ် ဝယ်ပါက မောင်မောင့်လိပ်စာကို ၁၀ ကြိမ် ရေးရမည် (Data Redundancy)။
* **Relational စနစ်တွင်**:
  * `customers` ဇယားတွင် မောင်မောင့် အချက်အလက်ကို ၁ ကြိမ်သာ သိမ်းသည်။
  * `orders` ဇယားတွင် မောင်မောင့် ID နံပါတ်ကိုသာ ညွှန်းဆိုလိုက်သည် (Clean & Normalized)။

## ၃။ Primary Key (PK) နှင့် Foreign Key (FK)

```
┌─────────────────────────────────┐
│         CUSTOMERS TABLE         │
├───────────────┬─────────────────┤
│ id (PK)       │ name            │
├───────────────┼─────────────────┤
│ 1 ◄─────┐     │ Ko Aung         │
│ 2       │     │ Ma Su           │
└─────────┼─────┴─────────────────┘
          │ ဆက်သွယ်မှု (Relation)
┌─────────┴───────────────────────┐
│          ORDERS TABLE           │
├───────────────┬─────────────────┤
│ order_id (PK) │ customer_id(FK) │
├───────────────┼─────────────────┤
│ 1001          │ 1               │
│ 1002          │ 1               │
└───────────────┴─────────────────┘
```

* **Primary Key (PK)**: နိုင်ငံသားစိစစ်ရေးကတ်ပြား နံပါတ်ကဲ့သို့ မည်သည့်အခါမျှ မထပ်သော သီးသန့်နံပါတ်။
* **Foreign Key (FK)**: အခြားဇယားရှိ Primary Key ကို လှမ်းခေါ်ထားသော တံတား။

## ၄။ ဘာကြောင့် Transaction (ACID) ကို မဖြစ်မနေ သုံးရတာလဲ?

မောင်မောင့် အကောင့်မှ ငွေ ၅ သောင်း လှလှ ထံသို့ လွှဲရာတွင် မောင်မောင့်ဆီမှ ငွေနုတ်ပြီးချိန်တွင် ဆာဗာ မီးပျက်သွားပါက ငွေ ၅ သောင်း လေထဲတွင် ပျောက်သွားမည်။

**Transaction** သည်:
* ငွေနုတ်ခြင်းနှင့် ငွေထည့်ခြင်း ၂ ခုစလုံး အောင်မြင်မှသာ **အကုန် အတည်ပြုမည် (`COMMIT`)**။
* အလယ်ခေါင်တွင် တစ်ခုခု ပျက်ကျပါက **ဘာမှ မဖြစ်ခဲ့သကဲ့သို့ မူလအခြေအနေသို့ ပြန်ဆုတ်ခွာမည် (`ROLLBACK`)**။

---

## ၅။ Database Index ဆိုတာဘာလဲ? မသုံးရင် ဘာဖြစ်မလဲ?

* စာမျက်နှာ ၅၀၀ ရှိသော စာအုပ်တွင် မာတိကာ (Index) မပါပါက စာမျက်နှာအားလုံး လှန်ဖတ်ရသည် (Full Table Scan)။
* Index ပါပါက အက္ခရာအလိုက် တိုက်ရိုက် သွားလှန်နိုင်သည် ($O(\log N)$)။
* **မသုံးရင် ဘာဖြစ်မလဲ?**: သုံးစွဲသူ ၁ သန်းကျော်လာပါက Website စာမျက်နှာတစ်ခု ဖွင့်ရန် ၃၀ စက္ကန့်ခန့် ကြာသွားပြီး Database CPU 100% ပြည့်ကာ Server ပြုတ်ကျသွားမည်။

---

## ၆။ SQL JOINs ဆိုတာဘာလဲ?

ဇယား ၂ ခု သို့မဟုတ် ထိုထက်ပိုသော ဇယားများကို ပေါင်းစပ်မေးမြန်းခြင်း:
* **`INNER JOIN`**: နှစ်ဖက်စလုံး Data တကယ်ရှိသော အပိုင်းကိုသာ ယူမည် (ဥပမာ- အော်ဒါအမှန်တကယ် ရှိသော ဖောက်သည်များ)။
* **`LEFT JOIN`**: ဘယ်ဘက်ဇယားရှိ Data အားလုံးကို အကုန်ယူမည် (ဥပမာ- အော်ဒါရှိသည်ဖြစ်စေ၊ မရှိသေးသည်ဖြစ်စေ ဖောက်သည်အားလုံး)။

## ၇။ MySQL နှင့် အခြား Database များ နှိုင်းယှဉ်ချက်

| Database | အမျိုးအစား | အားသာချက် | အသုံးပြုသည့် နေရာ |
| :--- | :--- | :--- | :--- |
| **MySQL** | **Relational (RDBMS)** | အလွန်မြန်ဆန်သည်၊ ရိုးရှင်းသည်၊ လူသုံးအများဆုံး | **Web Applications, E-Commerce, WordPress, SaaS** |
| **PostgreSQL**| Relational (ORDBMS) | Complex Queries များ၊ GIS ပထဝီဒေတာများတွင် သာလွန်သည် | Financial Systems, Big Analytics, Geo Apps |
| **MongoDB** | NoSQL (Document) | Schema အသေမရှိ၊ JSON တိုက်ရိုက်သိမ်းသည် | Chat Apps, Mobile Feeds, Real-time Gaming |

## ၈။ အစပြုသူတစ်ဦး လုပ်ငန်းခွင်တွင် လုပ်ဆောင်ရမည့် Tasks ဇယား

| ရက်သတ္တပတ် / ကာလ | လုပ်ငန်းခွင်တွင် ပေးအပ်ခံရမည့် တာဝန် (Real Work Task) | အသုံးပြုရမည့် Skills & Tools |
| :--- | :--- | :--- |
| **ရက်သတ္တပတ် ၁-၂** | DDL ဖြင့် Feature အသစ်အတွက် Table Schemas (Columns, Data types, Constraints) များ ရေးဆွဲပေးခြင်း | `CREATE TABLE`, `ALTER TABLE`, Constraints |
| **ရက်သတ္တပတ် ၃-၄** | Backend API များအတွက် လိုအပ်သော CRUD Queries နှင့် Filterings များ ရေးသားပေးခြင်း | `INSERT`, `UPDATE`, `SELECT`, `WHERE`, `ORDER BY` |
| **ရက်သတ္တပတ် ၅-၆** | Marketing အဖွဲ့အတွက် E-Commerce အရောင်းစာရင်း Reports များကို JOINs & Aggregations ဖြင့် ဆွဲထုတ်ပေးခြင်း | `INNER JOIN`, `LEFT JOIN`, `SUM`, `COUNT`, `GROUP BY` |
| **ရက်သတ္တပတ် ၇-၈** | နှေးကွေးနေသော Slow Queries များကို `EXPLAIN` ဖြင့် စစ်ဆေးပြီး Index တင်ကာ Speed မြှင့်ပေးခြင်း | `EXPLAIN ANALYZE`, Composite Indexes |
| **ရက်သတ္တပတ် ၉-၁၀** | ငွေလွှဲခြင်းနှင့် Checkout စနစ်များတွင် Race condition မဖြစ်စေရန် Transactions ချိန်ညှိခြင်း | `START TRANSACTION`, `FOR UPDATE`, `COMMIT` |
| **ရက်သတ္တပတ် ၁၁-၁၂**| Production Database Backup Cron Job စစ်ဆေးခြင်းနှင့် Staging Server ပေါ်သို့ Restore စမ်းသပ်ခြင်း | `mysqldump --single-transaction`, Point-in-time recovery |
